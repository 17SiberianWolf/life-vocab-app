## 1. 测试策略

### 1.1 测试分层

| 层次 | 手段 | 覆盖范围 |
|---|---|---|
| 静态校验 | Node 读取已构建的 `index.html` 做正则/JSON 断言 | 数据完整性、DOM 元素、CSS 规则、关键代码存在性 |
| 逻辑测试 | 抽取主应用 IIFE 在 Node 中 `eval` 执行 | 主 JS 语法正确性、函数可定义性 |
| 契约测试 | 校验 `data/*.json` 与数据库 schema 一致性 | 词库字段、去重、引用完整性 |
| 手工验证 | 真实浏览器（Chrome/Edge）操作 | 游戏体验、TTS、录音、云同步、PWA 安装 |

### 1.2 为什么不用 Jest / Playwright 全量自动化

| 考量 | 结论 |
|---|---|
| 项目规模 | 单文件应用，无模块打包，引入测试框架收益有限 |
| 环境依赖 | 构建产物是 HTML，直接文本断言最贴合实际运行时 |
| 沙箱限制 | 测试脚本**无法读取 `build_index.py` 源文件**，故统一改为校验已构建的 `index.html` |
| 成本 | 全量 E2E 需要浏览器驱动与云端账号，维护成本高 |

### 3.1 `test-tts.js` 说明（v1.0.1 新增）

发音链路无法在 Node 中真实发声，故采用**可控 mock + 时序断言**：从构建产物 `index.html` 中
截取 TTS 代码段（自包含，仅依赖注入的 `window / document / navigator / Audio / STATE`），
用 `new Function` 注入 mock 后导出内部函数逐一验证。

关键 mock 设计：

| mock | 说明 |
|---|---|
| `silentFail: true` | `speak()` 不触发 `onstart`，模拟手机端静默失败 |
| `voices: []` | 模拟 iOS / 国行 Android 首次 `getVoices()` 返回空 |
| `speaking: true` | 模拟正在播报，验证先 cancel 再延迟补播 |
| `withoutSynth: true` | 模拟微信内核等不支持 Web Speech 的环境 |

空白 utterance（`text === ' '`）与静音 wav（`data:` 开头）属手势解锁用途，断言时过滤，
避免干扰正常播报计数。

### 3.2 `test-spell.js` 说明（v1.1.0 新增）

拼写玩法含**纯函数**（判定/逐字符校验/提示遮罩）与**交互状态机**（回合推进/SRS 写入）两部分，
分别用两种手段验证：

| 层次 | 手段 | 断言内容 |
|---|---|---|
| 结构 & 移动端 | 对已构建 `index.html` 做正则断言 | 视图/导航/路由/生命周期接入；输入框 `inputmode/autocomplete/autocorrect/autocapitalize/spellcheck/enterkeyhint` 属性、字号 ≥16px、触控目标 ≥44px |
| 纯函数单元 | 从 `index.html` 截取函数段，`new Function` 沙箱执行 | 忽略大小写；**空格严格**（首尾/连续空格判错）；**非法字符严格**；逐字符定位 `firstSpellMismatch('stas','start')===3`、首字母错 `===0`、多打 `===5`；遮罩 `hintText('start',2)==='st___'` |
| 实时警示行为 | mock DOM 跑 `input` 事件处理器 | 正确前缀不警示；中间/首字母错 → 输入框变红 + 文本定位「第 N 个字符不正确」；改对后红框消失；多打字符提示 |
| 完整回合流程 | mock DOM + 受控定时器驱动真实游戏循环 | 答对写 `recordResult(true)`、+XP、连击、延迟推进；**连错 3 次仅记 1 次** `recordResult(false)` 并揭示答案；跳过不计分不写 SRS；提示揭示首字母 |
| 数据预检 | 遍历 `appData.cards` | 所有 `en` 无首尾/连续空格（严格判定前提）；可出题池 > 3000；每主题过滤后 ≥ 5 张 |

## 8. 测试维护规范

### 8.1 断言编写原则

**禁止硬编码会随数据演进而变化的数值。** 应改用：

| 反例 | 正解 |
|---|---|
| `cards.length === 158` | `cards.length >= 158` |
| `subscenes.length === 12` | `subscenes.length >= 12` |
| `modules.size === 12` | 校验「已声明子模块均有卡片」 |
| 全部卡强制有 `tip` | 区分精编卡与扩充卡 |

> D-09 就是违反此原则的真实案例：词库从 158 扩到 280 后，3 条断言误报失败。修复时改为**下界 + 结构完整性**断言，后续继续加词也不会再误报。

### 8.2 新增功能的测试要求

| 变更类型 | 必须补充 |
|---|---|
| 新增主题/词库扩充 | 跑 `test-business.js` + `test-stage5.js`，确认字段完整与零重复 |
| 新增游戏 | `test-stage3.js` 补充回合初始化与结算断言 |
| 修改算法 | `test-stage4.js` 补充边界用例 |
| 修改同步层 | `test-stage5.js` 补充契约断言 |
| **任何发布** | 跑全部 8 个套件 + 人工回归清单 §6.3 + bump `CACHE_NAME` |
